# 6.27 Supply-chain hardening and reproducible builds

This document is the execution artifact for task `6.27`:
`ai-task-manager/tasks/6-qday-crypto-by-default/6.27-supply-chain-reproducible-builds.md`.

## Goal

Harden the crypto artifact supply chain for `rust/crypto-engine` and `@okkey/crypto`
(WASM/SDK) using:

1. Pinned dependency and toolchain policy.
2. Deterministic/reproducible build checks.
3. Provenance generation and artifact attestation.

## In-Scope Surfaces

- Rust crypto engine: `rust/crypto-engine/**`.
- WASM and SDK build path: `packages/crypto/**`, `packages/types/**`, `scripts/**`.
- CI gates: `.github/workflows/security-suite.yml`,
  `.github/workflows/crypto-fuzz-quick.yml`,
  `.github/workflows/crypto-fuzz-extended.yml`,
  `.github/workflows/supply-chain.yml`.

## Dependency and Update Policy

### Lockfiles are mandatory

- JS workspace installs must use `yarn install --frozen-lockfile`.
- Rust build and tests must run against committed lockfiles.
- Canonical lockfiles:
  - `yarn.lock`
  - `rust/crypto-engine/Cargo.lock`
  - `rust/crypto-engine/fuzz/Cargo.lock`

### Pinned toolchains and build tools

- Rust stable toolchain is pinned in `rust-toolchain.toml`.
- Rust nightly fuzz lane is pinned by explicit date channel in CI.
- `wasm-pack` must be installed as a pinned version and with `--locked`.
- TypeScript compiler must come from repository dependencies, not runtime `npx -p`.

### Update workflow

1. Open PR with focused update scope (Rust crates, JS deps, or CI action pinning).
2. Include lockfile diff and impact summary.
3. Re-run supply-chain lane and security/fuzz lanes.
4. Attach updated evidence links if policy controls changed.

### Disallowed patterns

- Unpinned `latest` or floating installer scripts for build-critical tooling.
- Runtime package resolution via `npx --yes -p ...` in build/test scripts.
- Releasing or testing crypto artifacts from bootstrap placeholder package.

## Deterministic Build Controls

Implemented controls:

- Reproducibility script: `scripts/verify-crypto-reproducibility.mjs`.
- Build metadata/provenance script: `scripts/generate-crypto-provenance.mjs`.
- Provenance schema validation: `scripts/verify-crypto-provenance.mjs`.
- Bootstrap guard: placeholder `@okkey/crypto-wasm@0.0.0-bootstrap` is rejected
  after real build.

The reproducibility gate performs two clean builds with normalized env
(`SOURCE_DATE_EPOCH`, locale/timezone) and compares SHA-256 manifests for:

- `packages/crypto/dist/**`
- `packages/types/dist/**`

## CI Controls

### security-suite

- Uses pinned Rust toolchain from repository toolchain file.
- Installs pinned `wasm-pack` with `cargo install --locked`.
- Adds explicit check that bootstrap placeholder cannot pass post-build stage.

### supply-chain lane

- Runs reproducibility comparison and provenance generation.
- Validates provenance structure and checksum coverage.
- Uploads provenance bundle as CI artifact.
- Emits build attestation for provenance bundle artifact when
  repository/org supports GitHub attestations and
  `ENABLE_GITHUB_ATTESTATION=true` is set in repository variables.

## Local Runbook

From repo root `okkey/`:

1. `yarn install --frozen-lockfile`
2. `yarn build:wasm`
3. `yarn verify:crypto:bootstrap`
4. `yarn verify:crypto:repro`
5. `yarn build:crypto:provenance`
6. `yarn verify:crypto:provenance`

Expected outcome:

- Reproducibility script reports identical manifests for both builds.
- Provenance bundle is generated under `.artifacts/crypto-provenance`.
- Validation passes and CI attestation can be produced.
