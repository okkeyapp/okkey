# 6.24 Q-Day Threat Model

This document defines the Q-Day threat model used for external crypto review readiness.

## Security Objectives

1. Preserve zero-knowledge guarantees (backend never decrypts vault data).
2. Prevent downgrade to weaker crypto profiles in production.
3. Preserve confidentiality/integrity of shared key material and sync stream.
4. Preserve deterministic replay and rotation invariants.

## Assets

- Vault encrypted payloads (`EncryptedBlob`, event payloads, capsule payloads).
- Wrapped vault keys (`vault_keys.encrypted_vault_key`).
- User identity keys (Ed25519 + ML-KEM public keys and encrypted private bundles).
- Event-log version state (`events.payload_schema_version`, `vaults.crypto_version`).
- Signing envelopes and verification artifacts for critical events.
- Build/test evidence integrity for crypto path (CI workflows, fuzz outputs).

## Trust Boundaries

1. **Client trust zone**
   - Rust/WASM crypto operations, key generation, decrypt/encrypt/sign.
2. **Backend trust zone**
   - Stores ciphertext, enforces policy and invariants, verifies signatures.
3. **Storage boundary**
   - Postgres/Redis/object storage hold opaque encrypted artifacts.
4. **Delivery boundary**
   - CI pipelines and release artifacts for crypto engine and SDK packages.
5. **Enterprise extension boundary**
   - Extensions can attach but must not weaken Core crypto policy.

## Threat Actors

- External attacker manipulating API payloads and versions.
- Malicious or stale client attempting downgrade/replay/rollback flows.
- Compromised integration path attempting envelope/signature tampering.
- Supply-chain attacker attempting artifact/provenance drift.
- Operational misconfiguration at edge/ingress transport layer.

## Threat Scenarios and Controls

| Threat | Vector | Control | Evidence |
| --- | --- | --- | --- |
| Downgrade attack | Submit lower `crypto_version`/schema | Policy reject + stream floor checks | `docs/security/6.12-threat-to-test-matrix.md`, `docs/release_policy_qday.md` |
| Strip attack | Remove required envelope/version metadata | Request validation and shape checks | `docs/security/6.12-threat-to-test-matrix.md` |
| Missing PQ key in prod | Share/rotate to recipient without PQ key | Sharing policy enforcement | `services/api/test/security-qday-missing-pq-malformed-envelope.test.ts` |
| Malformed hybrid envelope | Corrupt wrap/envelope fields | Strict envelope validation + typed errors | `docs/architecture/14_crypto_v2_qday.md` |
| Replay/rollback | Duplicate/stale/gap event delivery | Replay invariants + fail-fast gap handling | `docs/architecture/05_sync_architecture.md`, `6.12` suite |
| Signature tampering | Alter critical event integrity envelope | Server verification gate (`SIGNATURE_INVALID`) | `docs/architecture/14_crypto_v2_qday.md` |
| Unsafe key transport | Put capsule keys in URL query/path | Transport policy reject + log redaction | `services/api/src/capsule/key-transport-policy.ts`, `capsules.routes` tests |
| Supply-chain drift | Placeholder artifact/provenance gaps | Reproducibility gate + provenance validation + attestation lane (`6.27`) | `docs/security/6.20-crypto-inventory-review.md`, `docs/security/6.27-supply-chain-reproducible-builds.md` |
| Edge TLS mismatch | Runtime ingress diverges from runbook | 6.19 runbook/checklist + ops evidence requirement | `docs/security/6.19-tls-transport-qday-*.md` |

## Residual Risks

1. Some transport/runtime evidence is external to Core repository and must be attached at handoff.
