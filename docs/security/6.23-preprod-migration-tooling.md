# 6.23 Pre-prod Migration Tooling (Internal Only)

This document defines how to run `v1 -> v2` migration tooling for **internal pre-prod/test datasets**.

## Scope

- Internal datasets only (local/dev/pre-prod fixtures).
- Migration updates metadata floors:
  - `events.payload_schema_version` (`<2` -> `2`)
  - `vaults.crypto_version` (reconciled to `max(2, MAX(events.payload_schema_version))`)
- Deterministic dry-run/apply reporting.

## Out of Scope

- Production client-data migration.
- Any launch-path dependency for first production release.

## Safety Rules

- Tool is blocked in production by default.
- `--apply` requires explicit `--confirm-preprod`.
- Production override is possible only with explicit environment variable:
  - `INTERNAL_PREPROD_MIGRATION_ALLOW_PROD=true`
  - This override is for emergency internal maintenance only and must not be part of standard release flow.

## Commands

From repository root:

- Dry-run:
  - `yarn tool:preprod-migrate:dry-run`
- Apply:
  - `yarn tool:preprod-migrate:apply --confirm-preprod`

If production override is absolutely required for internal operations:

- `INTERNAL_PREPROD_MIGRATION_ALLOW_PROD=true yarn tool:preprod-migrate:apply --confirm-preprod`

## Expected Report

Tool prints structured report with:

- mode (`dry-run` or `apply`)
- snapshot `before` / `after`
  - `totalVaults`, `totalEvents`
  - `legacyEvents`, `legacyVaults`
- `migratedEvents`, `migratedVaults` (apply mode)

## Verification Checklist

1. Run dry-run and save report.
2. Run apply with explicit confirmation.
3. Run dry-run again:
   - `legacyEvents = 0`
   - `legacyVaults = 0`
4. Repeat apply once more and verify idempotency:
   - `migratedEvents = 0`
   - `migratedVaults = 0`
