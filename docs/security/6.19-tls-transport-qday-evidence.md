### 4.1 Live rollback drill (Caddy stage, 2026-11-14)

This drill is the Caddy strict-policy rollback, not the nginx `OKKEY_COMPAT_*` compat-listener path (that path remains the dry-run above). Roll back a strict Caddy site by **deleting the `tls` block**. Do not replace it with an empty `tls { }`.

| Time (MSK) | UTC | Switch | Validate | Hybrid client | Classical X25519 | TLS 1.2 | HTTP status codes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 14:20:08 | 11:20:08 | default → **strict** | Valid configuration | `X25519MLKEM768` | refused (alert 40) | refused (alert 70) | unchanged |
| 14:21:44 | 11:21:44 | strict → **hybrid default** (`tls` directive removed) | Valid configuration | `X25519MLKEM768` | **accepted**, `Peer Temp Key: X25519` | accepted, `ECDHE-ECDSA-AES128-GCM-SHA256` | unchanged; legacy OpenSSL 3.0 client gets 401 again |
| 14:22:12 | 11:22:12 | hybrid → **strict** (final) | Valid configuration | `X25519MLKEM768` | refused (alert 40) | refused (alert 70) | unchanged; legacy client refused |

An earlier attempt at 14:20:25 MSK (11:20:25 UTC) used an empty `tls { }` block. Caddy rejects it (`parsing caddyfile tokens for 'tls': wrong argument count`). `caddy validate` caught it before any restart, so the running server stayed on strict. The drill was repeated by removing the directive entirely.

**Caddy rollback rule:** delete the `tls { ... }` block to return to Caddy's default hybrid. An empty `tls { }` is invalid and must not be used as the rollback edit.
