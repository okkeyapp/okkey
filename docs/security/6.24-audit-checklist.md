# 6.24 Audit Checklist and Evidence Pack

This checklist is used before handing off materials to an external crypto/security auditor.

## A. Package Integrity Checklist

- [x] Dossier entrypoint is present:
  - `docs/security/6.24-audit-readiness-dossier.md`
- [x] Threat model is present:
  - `docs/security/6.24-threat-model-qday.md`
- [x] High-risk rationale is present:
  - `docs/security/6.24-design-rationale.md`
- [x] Traceability matrix is present:
  - `docs/security/6.24-traceability-matrix.md`
- [x] Findings ownership and SLA are present:
  - `docs/security/6.24-findings-ownership.md`
- [x] Dry-review protocol notes are present:
  - `docs/security/6.24-dry-review-notes.md`

## B. Evidence Attachments Checklist

- [x] Threat-to-test mapping (`6.12`) is attached.
- [x] Fuzz/property triage and workflow refs (`6.13`) are attached.
- [x] Crypto inventory and risk matrix (`6.20`) are attached.
- [x] Key lifecycle evidence (`6.21`) is attached.
- [x] Rollout observability evidence (`6.22`) is attached.
- [x] Migration tooling scope guard (`6.23`) is attached.
- [x] Release policy gates/checklist are attached.
- [x] API/OpenAPI contract references are attached.
- [x] Fresh execution references for `test:security` and crypto quick lanes are attached in dry-review notes.

## C. Known Limitations (Must Be Explicit to Auditor)

| Item | Status | Backlog Link | Owner |
| --- | --- | --- | --- |
| Supply-chain reproducibility/provenance hardening | closed | `6.27` | Build/Release |
| Unified env crypto policy matrix (`dev/stage/prod`) | closed | `6.25` | Security + Backend |
| Transport runtime evidence outside core repo boundary | partial | `6.19`, `6.26` | Infra/SRE |

## D. Handoff Gate

External handoff is allowed only if:

1. Section A is complete.
2. Section B is complete.
3. Section C is explicitly included in handoff notes.
4. Findings ownership SLA is accepted by responsible roles.
5. Internal dry-review is completed and issues are triaged.
