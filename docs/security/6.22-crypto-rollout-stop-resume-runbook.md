# 6.22 Crypto Rollout Stop/Resume Runbook

This runbook defines operational procedures for emergency pause and safe resume
of Q-Day crypto write paths.

## Inputs

- `docs/security/6.22-crypto-rollout-observability-spec.md`
- `docs/security/6.19-tls-transport-qday-runbook.md`
- `services/api/src/config.ts`
- `services/api/.env.example`

## Runtime Gates

Control-plane variables:

- `CRYPTO_ROLLOUT_ENABLED=true|false`
- `CRYPTO_ROLLOUT_STATE=resume|stop`
- `CRYPTO_ROLLOUT_STOP_WRITE_PATHS=<csv paths or *>`

Supported write paths:

- `registration.complete`
- `sync.append`
- `vault.share`
- `vault.revoke`
- `vault.rotate`
- `vault.member_role_update`
- `capsule.create`

## Stop Procedure

1. Declare incident owner and create incident timeline.
2. Set `CRYPTO_ROLLOUT_STATE=stop`.
3. Set `CRYPTO_ROLLOUT_STOP_WRITE_PATHS=*` for global freeze, or target paths for scoped freeze.
4. Roll config (restart/redeploy API service according to env).
5. Validate that blocked writes return `CRYPTO_ROLLOUT_PAUSED`.
6. Confirm no secret leakage in logs/metrics.

## Resume Procedure

1. Confirm root-cause fix and rollback plan.
2. Switch to staged resume:
   - keep `CRYPTO_ROLLOUT_STATE=stop`
   - narrow `CRYPTO_ROLLOUT_STOP_WRITE_PATHS` to unaffected paths only
3. Observe `crypto.operation_total` and `crypto.rotation_failures_total` for 15m.
4. Set `CRYPTO_ROLLOUT_STATE=resume` when SLOs are stable.
5. Record evidence and close incident only after post-checks pass.

## Triage Matrix

| Signal | Likely cause | Immediate action |
| --- | --- | --- |
| `policy_violations_total` spike (`reason=policy`) | policy matrix/config drift | stop affected paths, verify env policy and release config |
| `policy_violations_total` spike (`reason=downgrade`) | downgrade/strip attempts or incompatible producer | freeze `sync.append`, validate client/version compatibility |
| `rotation_failures_total` spike | malformed wraps, stale membership, idempotency conflicts | stop `vault.rotate` and `vault.member_role_update`, run validation checks |
| `capability_coverage_total` blocked ratio rises | strict mode with non-PQ actors/devices | move staged lanes to compat or freeze impacted path |

## Evidence Checklist

- incident ID and owner;
- exact gate values used during stop/resume;
- screenshots/export of key metrics for stop and resume windows;
- confirmation of `CRYPTO_ROLLOUT_PAUSED` behavior in drill/test;
- post-incident corrective action with owner and deadline.
