# 6.24 Findings Ownership and Response SLA

This document defines ownership and response windows for potential findings from external crypto review.

## Ownership Matrix

| Finding Category | Primary Owner Role | Supporting Roles | Default Severity |
| --- | --- | --- | --- |
| Core crypto primitives / envelope correctness | Core Crypto | Core SDK, Security | high |
| Backend policy enforcement / anti-downgrade | Core Backend | Security | high |
| Replay/rotation invariants | Core Backend | QA, Security | high |
| Contract drift (API/OpenAPI/docs mismatch) | Architecture | Core Backend, SDK | medium |
| CI/fuzz/security gate regressions | Security + CI | Build/Release, QA | high |
| Supply-chain/provenance concerns | Build/Release | Security, Core Crypto | high |
| Transport runtime posture (edge/ingress) | Infra/SRE | Security | high |
| Core/Enterprise boundary violations | Architecture | Enterprise team, Security | medium |

## Response SLA

| Severity | Triage Start | Mitigation Plan | Fix Target | Escalation |
| --- | --- | --- | --- | --- |
| critical | <= 4h | <= 24h | <= 72h | Security lead + release stop |
| high | <= 1 business day | <= 2 business days | <= 7 business days | Security lead |
| medium | <= 2 business days | <= 5 business days | <= 1 release cycle | Area owner |
| low | <= 5 business days | <= 2 weeks | backlog prioritization | Area owner |

## Handling Process

1. Register finding in review log with severity and affected surfaces.
2. Assign owner role and supporting roles from matrix.
3. Add explicit remediation item to backlog with due date.
4. Record verification evidence (test/doc/proof) when closed.
5. If unresolved by SLA, escalate according to severity.

## Notes for Open Dependencies

- Findings touching reproducible builds/provenance map to task `6.27`.
- Findings on env policy harmonization map to task `6.25`.
- Findings on runtime transport configs map to task `6.26`/`6.19` evidence boundary.
