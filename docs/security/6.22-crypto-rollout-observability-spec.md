# 6.22 Crypto Rollout Observability Spec

Execution scope:

- `services/api/src/sync/service.ts`
- `services/api/src/vault-sharing/service.ts`
- `services/api/src/capsule/service.ts`
- `services/api/src/registration/service.ts`
- `services/api/src/crypto/policy-log.ts`
- `services/api/src/observability/crypto-rollout.ts`

## Goal

Provide rollout control-plane visibility for Q-Day crypto paths without exposing
secrets in logs/metrics.

Required risk categories:

1. capability coverage
2. downgrade attempts
3. rotation failures
4. policy violations

## Metric Dictionary

| Metric | Type | Source | Labels | Purpose |
| --- | --- | --- | --- | --- |
| `crypto.capability_coverage_total` | counter | capability decisions in registration/sharing/sync/capsules | `operation`, `mode`, `deploy_env`, `subject`, `result` | Track strict/compat rollout readiness and PQ-capable coverage |
| `crypto.policy_violations_total` | counter | `logCryptoPolicyViolation` | `reason`, `deploy_env`, `rollout_mode` | Detect policy/capability/downgrade reject pressure |
| `crypto.rotation_failures_total` | counter | vault rotation/revoke/role update failures | `operation`, `deploy_env`, `rollout_mode`, `code` | Detect instability in critical key-rotation paths |
| `crypto.operation_total` | counter | write-path wrappers | `operation`, `deploy_env`, `rollout_mode`, `outcome`, `code` | Unified success/error/blocked signal for rollout control plane |
| `crypto.operation_duration_ms` | histogram | write-path wrappers | `operation`, `deploy_env`, `rollout_mode` | Watch write-path latency regressions during rollout |

## SLI and SLO Targets

| SLI | Metric expression | SLO target | Window |
| --- | --- | --- | --- |
| Rollout write success ratio | `success / (success + error + blocked)` from `crypto.operation_total` | `>= 99.5%` in `prod` | 30m |
| Policy reject ratio | `policy_violations_total(reason=policy or downgrade) / operation_total` | `<= 0.5%` sustained | 30m |
| Rotation failure ratio | `rotation_failures_total / operation_total(operation=vault.rotate|vault.revoke|vault.member_role_update)` | `<= 1%` sustained | 30m |
| Capability readiness ratio | `capability_coverage_total(result=allowed) / capability_coverage_total` | `>= 99%` before strict rollout promotion | 24h |

## Cardinality and Redaction Rules

Mandatory constraints:

- no ciphertext, keys, passwords, or user PII in labels;
- use error codes and operation names only;
- never emit request payload fragments;
- labels must be bounded (`operation`, `reason`, `mode`, `code` from enum-like sets).

## Alert Baseline

Critical alerts:

- sustained policy/downgrade spikes above SLO threshold;
- sustained rotation failure ratio above threshold;
- rollout gate blocked writes in `prod` without active incident ticket.

Warning alerts:

- capability readiness dropping below promotion threshold;
- write-path latency p95 regression over baseline.

## Ownership

- Security: policy/downgrade/capability controls.
- Backend: instrumentation integrity and service-level behavior.
- Release: stop/resume decisions and incident sign-off.
